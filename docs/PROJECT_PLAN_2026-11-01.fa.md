# برنامهٔ اجرایی پروژه — ۱ نوامبر ۲۰۲۶

> **یادداشت وضعیت:** این سند تصویر برنامه در ۱ نوامبر است و ترتیب فعلی اجرا را نشان نمی‌دهد. تصمیم‌های مالک در ۴ نوامبر در [STAGED_DEVELOPMENT](STAGED_DEVELOPMENT.md) و کامنت‌های ایشوهای GitHub ثبت شده‌اند؛ از جمله بسته‌شدن #5 و #18، فعال‌بودن #15 به‌عنوان گام بعدی، و مقصد بودن V2 در شاخهٔ محلی. جدول زیر برای نگهداری سابقه باقی مانده است.

این برنامه پس از بررسی وضعیت همهٔ ایشوهای #1 تا #28 و کامنت‌های تصمیم‌ساز GitHub تهیه شده است. مرجع پیگیری: [نقشهٔ ایشو #28](https://github.com/arashashrafii/astro-static-studio/issues/28). این برنامه برنامه‌ریزی است؛ تصمیم معماری یا مجوز توسعهٔ قابلیت جدید نیست.

## اقدام فعلی: آزمون واقعی داشبورد

**اولویت P0 — #5: آزمون سناریو توسط عامل تست.** سناریوی آماده در [ISSUE_5_OWNER_TEST.fa.md](ISSUE_5_OWNER_TEST.fa.md) اجرا شد. نخستین backup روی ۲۳۸ تصویر بیش از ۹۰ ثانیه طول کشید و UI را معطل می‌کرد. رفع در `backup.ts` با حفظ decode کامل، فایل را در حدود ۲۵–۳۰ ثانیه تولید می‌کند؛ API درخواست‌های هم‌زمان را سریالی می‌کند. تست‌های backup (۹ مورد) و typecheck موفق‌اند. بازآزمایی عامل: دو backup معتبر دریافت شد؛ پروژهٔ آزمایشی، متن، سه عکس، alt و ترتیب پس از ذخیره/بارگذاری مجدد حفظ شدند؛ پیش‌نمایش محلی و متن اصلاح‌شده بررسی شد. انتخاب‌گر بومی سیستم‌عامل دیده نشد، اما upload از ورودی UI و filechooser مستند CUA انجام شد. پنل انتشار بازبینی شد؛ بدون اتصال Cloudflare، کنترل‌های پیش‌نمایش/عمومی در دسترس نبودند و اتصال طبق سناریو انجام نشد. پروژهٔ آزمایشی برای بازبینی مالک فعال و باقی است. این شواهد اجرای عامل است، نه پذیرش نهایی مالک؛ #5 باز می‌ماند. انتشار، حذف و restore انجام نشدند.

- مالک محصول و بازبینی گزارش: کاربر.
- هماهنگ‌کننده و مدیر ایشو: مدیر این گفتگو.
- اجراکنندهٔ پیاده‌سازی: عامل توسعه، فقط برای ایشوی کوچکِ تعیین‌شده پس از بازبینی مالک.
- تستر: عامل تست برای اجرای سناریو و ثبت مشاهدات؛ گزارش او به مالک می‌رسد و با پذیرش انسانی یکی فرض نمی‌شود.
- خروجی/اتمام: یادداشت محیط، نتیجهٔ هر گام، گیرها و بزرگ‌ترین ابهام؛ سپس تبدیل هر مشاهده به کار مستقل و کوچک. هیچ معیار #5 با این برنامه حذف یا تکمیل نمی‌شود.

## قیود محصول و مرز شواهد

- فهرست قالب‌ها در هدف محصول آنلاین است؛ فقط قالب‌های استاندارد و ازپیش‌تأییدشده نشان داده می‌شوند. کاربر قالب منتخب را روی دستگاه دانلود می‌کند؛ آماده‌سازی/build وابستگی‌ها را می‌گیرد. این چرخه هنوز قابلیت اثبات‌شده نیست.
- دانلود dependency، محل اجرای build، شروع سرد برنامه/runtime، build سرد/گرم، preview و publish مراحل و شواهد جدا هستند. موفقیت یک مرحله اثبات مرحلهٔ دیگر نیست.
- کاربران داخل ایران ممکن است با GitHub و مقصدهای میزبانی دلخواه محدودیت داشته باشند؛ GitHub/Cloudflare را پیش‌فرض اجباری آینده نکنید. گزینهٔ GitHub Actions یا build service مستقل تصویب نشده و در این برنامه انتخاب معماری نمی‌شود.
- تولید ZIP سایت با backup قابل‌ویرایش فرق دارد؛ معیار و آزمون هر خروجی جداست. Content v1 و حفاظت backup/loopback API فعلی حفظ می‌شوند تا مهاجرت جداگانه تصویب و آزمون شود.
- گزارش [بررسی مستقل معماری](INDEPENDENT_ARCHITECTURE_REVIEW_2026-11-01.fa.md) پیشنهاد است، نه مصوبه. اسناد محلی و PoCهای uncommitted شاهد وضعیت فایل‌های workspace هستند، نه محتوای منتشرشدهٔ شاخهٔ GitHub.
- هیچ issue بر اساس وجود کد/سند به‌تنهایی بسته نمی‌شود؛ production اعلام‌شده یا مجاز نیست؛ ویژگی یا معماری جدید در این مرحله شروع نمی‌شود.

## نقش‌ها و پیگیری

مالک محصول/تصمیم/پذیرش: کاربر. هماهنگی، مدیریت dependency و به‌روزرسانی نقشه: مدیر پروژهٔ این گفتگو. اجراکننده و تستر فنی برای هر issue فقط هنگام آغاز همان کار مشخص می‌شوند. مسئولیت‌ها نقشی‌اند؛ حساب GitHub ساختگی به‌عنوان assignee تعیین نمی‌شود. این مدل تیم دائمی یا زنجیرهٔ ثابت مدیر-اجراکننده-تستر ایجاد نمی‌کند.
